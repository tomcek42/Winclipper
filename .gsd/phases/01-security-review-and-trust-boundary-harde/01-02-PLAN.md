# S02: Validate fields before size and allocation use

**Milestone:** M001
**Slice:** S02

**Goal:** Harden all field validation and arithmetic guardrails so attacker-controlled or malformed local data cannot cause underflow, overflow, or invalid allocation behavior.
**Demo:** Malformed persisted data is rejected before any size arithmetic or allocation occurs, and read failures are treated as data corruption instead of silent success.

## Must-Haves

- No unsigned subtraction occurs without ordering validation.
- All read/readsome return values are checked before use.
- Critical file fields are bounded or rejected before arithmetic or allocation.
- Malformed or incomplete persisted data fails safely and predictably.

## Proof Level

- This slice proves: Targeted contract verification with malformed-input regression checks and compile validation

## Integration Closure

This slice is the core security fix that downstream validation and persistence work depends on.
